# Printify

Print-on-demand selling, run by the person's agent: browse Printify's catalog, start a product with a design, create it in the person's Printify shop and publish it to the shop's sales channel (Etsy, Shopify, eBay, TikTok Shop, WooCommerce…) once the person confirms, then follow products, orders and profit. Through the REST API at `https://api.printify.com/v1` (reference at https://developers.printify.com/). Printify makes and ships each order; the sales channel collects the buyer's money and pays it out.

| stage          | how                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| search         | `GET /catalog/blueprints.json`, filtered here by the words in title, brand, model and description. Each blueprint is a task `bp-<id>`.                                                                                                                                                                                                                                                                                                                                                                                                       |
| get            | `GET /catalog/blueprints/{id}.json` and `/catalog/blueprints/{id}/print_providers.json`; the providers are listed in the description with their `print_provider_id`.                                                                                                                                                                                                                                                                                                                                                                         |
| apply          | `bp-<id>` starts a draft `d-<hex>` kept in `printify-drafts.json` in the cache folder (per tenant when hosted). Answers: `title` (needed), `price` (per item, stored in cents), `description`, `tags` (up to 13), `print_provider_id` (else the first provider), `colors`, `sizes`, `position` (`front` or `back`). Applying to the draft's id again changes it.                                                                                                                                                                             |
| upload, remove | One design per draft. A file goes to `POST /uploads/images.json` as `{ file_name, contents }` (base64); an https link in text as `{ file_name, url }`. A new upload replaces the design. remove forgets it and archives the upload (`POST /uploads/{id}/archive.json`, best effort).                                                                                                                                                                                                                                                         |
| submit         | Only with `note` set to `confirm:<token>` from apply or status; the token hashes the draft's title, price, design, provider and last change. Then `GET .../print_providers/{pid}/variants.json` (narrowed to the asked colors and sizes, up to 100), `POST /shops/{shop}/products.json` with every variant at the price and the design centered on the placeholder, and `POST /shops/{shop}/products/{id}/publish.json`. A shop whose `sales_channel` has nothing to publish to (custom, disconnected) gets the product but no publish call. |
| status, list   | A draft is `work_needed`. A submitted one reads `GET /shops/{shop}/products/{id}.json` and the latest 50 orders (`/orders.json`, 10 a page): `external.id` set means on sale (`applied`), `is_locked` means publishing (`in_review`), paid orders make it `accepted` with the profit. list also returns the shop's products as `p-<product id>`.                                                                                                                                                                                             |
| account        | `GET /shops.json`: the shop used (`PRINTIFY_SHOP_ID` or the first) and its sales channel.                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| earnings       | The latest 50 orders: per line, `metadata.price × quantity` less `cost × quantity + shipping_cost`. Fulfilled orders are `available`, others `pending`; canceled, unfulfillable and unpaid ones are left out. No payout: the sales channel pays out.                                                                                                                                                                                                                                                                                         |

**Auth.** `PRINTIFY_API_TOKEN` is a personal access token from https://printify.com/app/account/api, sent as `Authorization: Bearer` with the connector's User-Agent. Scopes: `shops.read catalog.read products.read products.write uploads.read uploads.write orders.read`. `PRINTIFY_SHOP_ID` picks a shop when the account has more than one.

Rate limits are Printify's: 600 requests a minute, 100 a minute on the catalog, 200 publishes per 30 minutes. A 429 becomes `rate_limited`.

No Printify account was available, so nothing here has run against the live API; the fixtures follow the reference (checked 2026-10-29). Not confirmed live: whether line-item `cost` is per item (it is multiplied by quantity here) and `shipping_cost` per line; which `sales_channel` values publish (the set here is a guess beyond etsy and shopify); that the publish call lists the product on its own for a connected Etsy or Shopify shop rather than waiting for `publishing_succeeded.json` (the reference describes that for custom integrations); and the orders list's pagination field (`last_page` is read when present). The first product should be published by hand from the agent's draft.
