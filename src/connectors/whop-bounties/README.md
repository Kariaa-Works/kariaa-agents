# Whop bounties

Paid tasks posted on Whop: clipping, UGC, post engagement, account growth, local activations and data capture. Each bounty's reward sits in escrow and pays a fixed amount per accepted submission into the worker's Whop balance. Through Whop's REST API (`https://api.whop.com/api/v1`, pinned to `Api-Version-Date: 2026-10-15-1`).

| stage          | how                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| search         | `GET /bounties?status=open`: the bounties your account can see and work. Words are matched here against the title, description and goal; a place becomes the API's `country` filter (bounties open worldwide always match).                                                                                                                                                                                                                                                   |
| get            | `GET /bounties/{id}`; a public bounty needs no token                                                                                                                                                                                                                                                                                                                                                                                                                          |
| apply          | Standard bounties have no claim step: apply keeps a local draft. Data capture: `POST /bounty_submissions` without a deliverable claims an attempt, with `affiliate_code` and the capture metadata from `answers`. The metadata goes with the claim only, whole or not at all: `city`, `country`, `device`, `operator`, `site` and `station`, plus `fov` in whole degrees if known. It is required when the bounty's capture spec lists fields; `get` shows them as questions. |
| upload, remove | A file: `POST /files`, then the bytes `PUT` to the returned `upload_url`. Text: its links join the deliverable and the rest becomes the caption. Up to 10 links and 10 files; remove drops one from the draft.                                                                                                                                                                                                                                                                |
| submit         | Standard: `POST /bounty_submissions` with `deliverable: { urls, file_ids, caption }` (links in `note` count too); it goes straight to the poster's review. A claimed attempt (`btys_`): `POST /bounty_submissions/{id}/submit`.                                                                                                                                                                                                                                               |
| status, list   | `GET /bounty_submissions/{id}` and `GET /bounty_submissions` (your own): `in_progress` is `work_needed`, `submitted` is `in_review`, `approved` is `accepted`, `denied` is `rejected` with the reason                                                                                                                                                                                                                                                                         |
| account        | `GET /users/me`                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| earnings       | `GET /users/me` (balance, lifetime income), your approved submissions with their rewards, `GET /payouts` and `GET /payouts/methods`                                                                                                                                                                                                                                                                                                                                           |
| payout         | `POST /payouts` from your balance to a saved payout method, matched in `GET /payouts/methods` by its id, `default`, or a word from its name or rail (`paypal`, `bank_deposit`). Without `amount` the whole withdrawable balance goes, rounded down to the cent; `note` becomes the payout's notes (up to 255 characters).                                                                                                                                                     |

**Auth.** `WHOP_OAUTH_TOKEN` is a Whop user OAuth token. Create an app at https://whop.com/dashboard/developer, request `bounty:basic:read`, `bounty:submission:create`, `user:balance:read`, `payout:withdrawal:read`, `payout:destination:read` and `payout:withdraw_funds`, and sign in through it ([OAuth guide](https://docs.whop.com/developer/guides/oauth)). An access token lasts one hour; the refresh token from the same sign-in gets the next one. Account API keys cannot author submissions. All-source searches skip Whop while the token is unset; reading a bounty by id works without it.

**Review and pay.** The poster approves or denies each submission in Whop. There are no webhooks, so `status` polls. An approved submission pays the bounty's net reward into your Whop balance. Data-capture clips and livestream proof are recorded in the Whop app; `submit` sends the attempt once the footage is in.

Links and files added before `submit` wait in `whop-bounties-drafts.json` under `WORK_CACHE_DIR` (default `~/.cache/work-protocol`). `url` is the hosting account's Whop page. Whop's [developer API terms](https://whop.com/tos-developer-api/) apply.

Checked live on 2026-10-20: `GET /bounties/{id}` answers without a token and `GET /bounties` asks for one, as documented. Listing bounties needs an account, so the fixtures follow the examples in the API reference. The submission, file upload and payout shapes follow the API reference and have not been run against a live account yet; the first real submission and the first payout should be done by hand.
