# Algora

Open-source bounties on GitHub issues, priced and paid through [Algora](https://algora.io). A maintainer or sponsor puts money on an issue, contributors post `/attempt`, the author of the merged fix posts `/claim`, and the maintainers award it. Algora pays the award in fiat through Stripe Connect.

Algora has no public JSON API to read from any more. `console.algora.io/api/orgs/{org}/bounties` redirects to a 404 on algora.io, the tRPC `bounty.list` answers an empty list for every input, and the bounty boards are LiveView pages. So the connector reads GitHub. An issue counts as an Algora bounty only when `algora-pbc[bot]` has commented `## 💎 $X bounty [• Sponsor](…)` on it. That comment is both the proof and the price. The `💎 Bounty` label alone is not enough, because anyone can create it: on 2026-10-27, most open issues carrying it belonged to label farms whose look-alike comments come from other bots.

| stage   | how                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| search  | `GET /search/issues` with `org:<each trusted org> commenter:algora-pbc[bot] state:open is:issue archived:false`, split across queries to stay under GitHub's 256-character limit. Qualifiers in the person's words are dropped, so a search never leaves the trusted organisations. Each hit's comments are then read (`GET /repos/{o}/{r}/issues/{n}/comments`) to confirm and price the bounty. Left out: rewarded issues (`💰 Rewarded`, or the bot's `🎉🎈 @user has been awarded`), and issues labelled core-team-only or on hold. |
| get     | `GET /repos/{o}/{r}/issues/{n}` and its comments. Ids look like `owner/repo#123`; the issue URL works too.                                                                                                                                                                                                                                                                                                                                                                                                                              |
| apply   | Drafts `/attempt #N` (with the plan from `note`) and posts nothing. It returns a preview and `submit with note "confirm:<token>"`. If the person already attempted, it records that instead.                                                                                                                                                                                                                                                                                                                                            |
| submit  | `confirm:<token>` posts the drafted attempt: `POST /repos/{o}/{r}/issues/{n}/comments`. `pr:<PR URL>` drafts `/claim #N` for that pull request and returns a confirm token; `confirm:<token>` then posts it (`/claim <issue URL>` when the PR is in another repository). The PR must be the person's own, because Algora pays the PR's author; a PR by anyone else is refused. Nothing is posted when the PR description already claims the issue.                                                                                      |
| status  | Reads the issue and its comments. The person's award is `accepted` (with the amount), someone else's award or a closed issue is `closed`, a claim is `in_review`, an attempt is `work_needed`.                                                                                                                                                                                                                                                                                                                                          |
| list    | Every attempt in the local state file, each through status.                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| link    | The claim comment, the attempt comment, or the issue.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| account | `GET /user`, plus the token's `x-oauth-scopes`. Commenting on other people's repositories needs a classic token with `public_repo`.                                                                                                                                                                                                                                                                                                                                                                                                     |

**Auth.** `GITHUB_TOKEN` is a classic personal access token with the `public_repo` scope ([create one](https://github.com/settings/tokens/new?scopes=public_repo&description=work-protocol)). It is required for apply, submit, status and list. Search and get work without it, but GitHub then allows 10 searches a minute and 60 other requests an hour, and every search reads one comment thread per hit. With a token those limits are 30 searches a minute and 5,000 requests an hour.

**Organisations.** `ALGORA_ORGS` (comma separated) replaces the default list: `tscircuit, zio, coollabsio, highlight, gyroflow, go-gitea, onyx-dot-app, tailcallhq, permitio, revertinc`. Each had at least one open, unrewarded bounty with an `algora-pbc[bot]` pricing comment on 2026-10-27. calcom, triggerdotdev, golemcloud, archestra-ai and projectdiscovery had none open that day, so they are not in the default. A bounty can have several sponsors; the newest pricing comment lists all of them and the pay is their sum.

**Getting paid.** Algora pays through Stripe Connect on algora.io: sign in there with the same GitHub account and finish the payout setup. There are no earnings or payout stages, because GitHub shows the award but not the money.

Attempts are kept in `algora-attempts.json` under `WORK_CACHE_DIR` (default `~/.cache/work-protocol`).

Checked live on 2026-10-27 with read-only GETs: the issue search, issue, comment and pull-request reads; the bot's pricing, claim and award comment formats; and the `💎 Bounty` and `💰 Rewarded` labels. `fixtures/search.json`, `comments.json`, `rewarded-issue.json`, `rewarded-comments.json` and `pull.json` are trimmed captures. `user.json` and `comment-created.json` follow GitHub's REST reference. Posting `/attempt` and `/claim` has not been run live yet, so the first real attempt should be watched.
